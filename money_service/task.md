# Задание: Разработка API-сервиса финансовых операций

## 1. Цель

Разработать веб-приложение на Flask для создания финансовых операций — приходных (income) и расходных (expense) — с сохранением данных в in-memory SQLite (без внешней СУБД и без сохранения на диск).

## 2. Стек технологий

- Python 3.11+
- Flask 3.x
- SQLAlchemy 2.x (declarative `Base`, `Mapped` / `mapped_column`)
- Хранилище: SQLite in-memory (`sqlite:///:memory:`)
- Тестирование: pytest + coverage
- Линтинг: ruff

## 3. Модели данных

**Category** (справочник категорий):
- `id` — integer primary key
- `name` — строка, обязательна, уникальна глобально, длина 1–100 символов (после обрезки пробелов)
- `type` — enum: `income` | `expense`

**Operation** (финансовая операция):
- `id` — integer primary key
- `type` — enum: `income` | `expense`
- `amount` — integer, количество минимальных единиц (копеек), строго > 0
- `category_id` — FK на `Category.id`, обязателен
- `comment` — строка, опциональна, до 500 символов
- `created_at` — timestamp UTC, устанавливается сервером

Схема создаётся через `Base.metadata.create_all()` при старте приложения. Внешние миграции не требуются.

## 4. Эндпоинты и формат API

### `POST /categories`

Тело: `{"name": "Продукты", "type": "expense"}`
- Успех: `201` + JSON созданной категории
- Невалидное тело (нечитаемый JSON, отсутствующие поля, пустой/длинный `name`, неверный `type`) → `400`
- Дубликат `name` → `409`

### `POST /operations`

Тело: `{"type": "expense", "amount": 25000, "category_id": 1, "comment": "Супермаркет"}`

Ответ успеха `201`:

```json
{"id": 1, "type": "expense", "amount": 25000, "category_id": 1,
 "comment": "Супермаркет", "created_at": "2026-09-22T12:00:00Z"}
```

Правила валидации операции (`amount` и `category_id` в JSON — целые числа, `amount` в копейках):
- Нечитаемый JSON или отсутствующие обязательные поля → `400`
- `amount` — целое > 0; `type` — строго `income` или `expense`; некорректный `category_id` (отсутствует/нечисловой) → `400`
- `category_id` существует → иначе `404`; тип категории соответствует типу операции → иначе `400`
- Ошибки возвращаются как JSON: `{"error": "<описание>"}`

## 5. Архитектура

- Application factory: `create_app()` в `app/__init__.py`
- Blueprint для эндпоинтов категорий и операций
- Слой репозитория (`CategoryRepository`, `OperationRepository`) между маршрутами и SQLAlchemy — обязательно, чтобы мокать его в unit-тестах
- Сервисный слой между маршрутами и репозиториями — опционален
- Engine для in-memory SQLite: `poolclass=StaticPool`, `connect_args={"check_same_thread": False}` (иначе каждая сессия получит пустую БД)

## 6. Тестирование

- **Обязательны unit-тесты** c mock/monkeypatch: логика валидации и обработчики маршрутов тестируются с замоканным репозиторием (без обращения к БД).
- Покрытие приложения (`app/`) — не ниже 80%.
- Интеграционные и e2e-тесты **не требуются** (допускаются как бонус: in-memory SQLite не требует внешней инфраструктуры).

## 7. Качество кода

- `ruff check` и `ruff format` — без ошибок
- mypy не требуется

## 8. Структура сдаваемых материалов

```
money_service/
├── app/            # приложение (factory, blueprints, models, repositories)
├── tests/          # unit-тесты
├── pyproject.toml  # зависимости, конфигурация pytest/ruff/coverage
└── README.md       # запуск и тестирование
```

Запуск: `flask --app app run`. Тесты: `pytest --cov=app`.

## 9. Критерии приёмки

1. `POST /categories` создаёт категорию (`201` + JSON); дубликат `name` → `409`.
2. `POST /operations` создаёт приходную или расходную операцию (`201` + JSON).
3. Нарушения валидации возвращают `400`, ссылка на несуществующую категорию — `404`; все ошибки — JSON с полем `error`.
4. Тип операции и тип категории согласованы: приход нельзя отнести к расходной категории.
5. Данные сохраняются в in-memory SQLite и доступны в рамках запущенного процесса приложения.
6. Unit-тесты с mock/monkeypatch проходят; покрытие `app/` ≥ 80%; ruff без замечаний.
7. Приложение запускается одной командой без внешних сервисов.
